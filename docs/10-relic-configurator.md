# 遗物配置器：开发与实机进度

用户已要求持续推进任务书中的遗物自选，不以单个实验通过结束开发。

## 已实现

- Windows本地窗口：职业筛选、词条名称/ID搜索、选取/移除、难度额度、保存/载入JSON预设。
- 普通候选目前采用经追踪的100/101/102模板来源，共290条，避免将未确认的特殊模板直接混入。
- 重复词条、同compatibility/exclusivity分组暂按保守规则拒绝；不能宣称这是完整原生合法性判定。
- 深夜按2000000/2200000/3000000池区分需要负面、无负面与负面候选，要求正负一起保存。
  本机两类正面池不重叠；深夜单件正负绑定、装备/卸下与无补丁保留已通过实机。
- 单遗物1–3条预设可导出实验清单，并通过通用构建器生成可回读校验的参数补丁。
- 构建固定原件散列、表/行/字段原值，比较所有实际变化及其他资源；输出仅允许在local目录。

## 实机证据

EXP-RELIC002使用商店固定绿色遗物1270。用户确认三条自选属性有效、数值符合词条。
精确面板数值和卸下恢复尚未逐项记录，因此不补造数值。
该实验只证明引用修改能进入游戏，并非最终合法遗物输出方案。

EXP-RELIC003改用原生绿色随机遗物129，通过ShopLineup10041提供获取入口。
三个词条分别属于该原件槽位池300/200/100；只固定获得结果，不改词条本身。
用户已确认购买/装备有效，撤除补丁后词条保留且有效，卸下后加成消失。生成期间模板129会全局受影响，
因此仅供隔离单人测试，尚不满足多人独立配置。

## 使用

```powershell
Set-Location 'E:\\Codex\\Project\\黑环mod'
pwsh -File tools/start_configurator.ps1
python tools/relic_presets.py --preset local/presets/EXP-RELIC002-three-stats.json
```

窗口保存预设草稿，“导出实验清单”和“生成隔离实验包”现使用随机遗物路线。
1–3条分配一件，4–6条分配两件绿色遗物，并检查本职业适配容器。单件三词条与双件六词条均已通过实机。
生成包含generate.me3和play.me3，后者不加载参数补丁。包使用唯一隔离存档名，不自动写正式存档。
构建例子（必须提供全新输出目录）：

```powershell
pwsh -File tools/build_param_patch.ps1 -Manifest 'E:\\Codex\\Project\\黑环mod\\local\\evidence\\EXP-RELIC003-manifest.json' -OutputDirectory 'E:\\Codex\\Project\\黑环mod\\local\\relic003-rebuild\\mod'
```

GUI使用系统Python/Tk；构建使用带.NET10的PowerShell7与固定Smithbox库。
这里未包含一键修改正式存档、内存写入或自动连接联机的功能。

## 外部依据与不确定性

- [Nightreign Data Tools查询](https://github.com/ParaphrazeTutorials/nightreign-data-tools/blob/main/downloads/reliquary/queries/reliquary.sql)
  将普通/深夜/负面池区分，并提供DLC权重覆盖及排序线索。本机定义为s16的-1，未照搬其255表示法。
- [独立校验工具规则](https://github.com/SEANPNEX/nightregin_relic_verifier/blob/main/ruleset.md)
  区分固定预设与随机遗物，并描述槽位、互斥及负面绑定。
- [速度挑战编辑器](https://github.com/Doublemoses/NightreignRelicEditor)
  展示了选择、预设和运行时应用先例。这里只研究行为说明，未运行其程序或移植内存写入。

这些都是社区证据，不是游戏官方提供的接口。不同工具对排序检查范围的描述不同，
本项目采取保守排序，并继续依靠本机原件与离线实机验证。没有复制上述项目源码或捆绑其数据。
