# 联机、视觉资产和工程规范

## 联机设计（待原生适配证明）

状态键：expedition_id + player_id + buff_id；敌人效果另加 entity_id + spawn_generation。
事件：event_id、root_event_id、source_player、owner、reward_id、state_version、config_hash、
sequence、timestamp、payload。ID不可用进程地址或当前队伍槽位充当跨重连身份。
这些是NRE内部数据契约，不是声称游戏现成字段。

规划让权威端提交奖励结果与敌人触发，玩家端提出请求；先验证能否用原生同步状态承载。
未找到可用传输/身份接口前不实现虚构 Seamless API。房主不覆盖玩家遗物预设。
每次确认事件幂等去重，同根递归保护，状态版本单调；断线有快照+确认序号恢复，
无法可靠恢复则暂不支持继续该远征构筑，并显式提示测试限制。
召唤由一个权威端生成，归属单一玩家，死亡/断线/卸载销毁；客户端只观察结果。

双人、三人测试矩阵：不同职业与不同构筑；两人同击一个敌人；同刻触发同Buff；
持有人/非持有人/房主死亡；倒地救起；掉线重连；Boss门/地图卸载；远征成功与失败；
交换房主身份重新开局。记录重复事件数、丢失事件数、效果次数、状态散列与帧耗时。
4–6人作为后续，不能由三人通过推定可用。官方匹配不作测试环境。

[MMV配置先例](https://github.com/eepycloud/More-Map-Variations-MMV-Seamless-Coop)
使用 nrsc.dll 提前加载，并指出不能同时装载其 Server Redirector；这仅提供加载线索。
Seamless 的作者页不保证其他Mod兼容，因此本工程兼容状态始终待测。

## 图标规范

第一阶段只做规范；不复制其他 Mod 或游戏拆包素材进仓库。
原创母版建议 512×512 PNG RGBA，外部配置器导出128/64/32预览；这些不是已确认游戏UI尺寸。
主体居中，边缘留8%，暗金金属/骨/石为基础，各系列共享光向；
红色风险以裂纹和血色辅纹表达，避免只靠颜色区分。32px须可辨轮廓。
命名 `nre_talisman_<internal_name>_v001.png`。
映射见 assets/icons.json：游戏图集、纹理格式、索引全部空，需检查当前NR菜单纹理、
图集布局、压缩和索引分配后填写。先原有图标占位只在本地使用，不再分发拆出图。

## 追踪、回滚和迁移

本地Git主分支 main，功能分支 codex/<topic>。本轮不建GitHub、不push。
提交分层：研究/设计；数据；工具/测试；实际映射。任何映射附版本和实验编号。
未来用户明确要求远程仓库时再配置 private remote，上传前审计资源与许可证。
更新目标版本时：原件只读存档→新散列→新版定义→引用/字段差异→补丁预条件→实机回归。
无法映射的条目停用，不按名称猜ID。回滚使用Git恢复源与禁用加载配置，不回写游戏目录。

工具链可复现清单包括工具release/commit、SHA256、原件SHA256、导出CSV、补丁、修改后SHA256。
游戏原件和二进制留 local；可审计字段差异可本地记录，不自动公开完整原生表。
