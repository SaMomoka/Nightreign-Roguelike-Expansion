# 抽取、叠加、联动规则草案

本文及 data/rules.json 的概率为可调设计值，不是游戏原生概率。当前没有运行时抽奖实现。

## 事务边界

一次奖励使用 `(expedition_id, player_id, reward_id, revision)` 唯一键。
先确定已提交的拥有状态，再过滤不满足职业、前置、互斥、层数上限、游戏映射验证条件的条目。
未启用的条目永不进入实机池。前置未知时关闭该候选，避免无效奖励。

在合格池按稀有度权重抽类别，再按类别内条目权重抽条目；每次候选内部无放回。
70/25/4/1 分别是普通/稀有/金/红的初始权重，过滤后空类剔除并重新归一化。
4% 不是“三选一含金概率”；三槽、无放回、空类及动态加权都会改变最终概率。
不足三个时只展示有效数量，不补无效机制；没有任何候选则保留原生奖励流程。
目标是三选一，接 UI 失败不能默默改为自动领取。

相关构筑权重乘数最多 2 倍；可保留 10% 的选择尝试用于无协同的合法候选。
这不是绕开硬前置的概率。随机种子绑定远征/玩家/奖励/刷新序号，记录算法版本。
主客机不能各抽一次再相信“相同种子”；提交结果须由未来证实可用的权威端确认。

数值 Buff 重复获得至上限；同轮候选不重复，但后续奖励可再次出现。
同一个数值定义先按基础值加算到上限，禁止每层反复乘算失控；实际 SpEffect 是否覆盖、
只取最高或可叠加需实验决定映射。机制只获得一次，领取原子地去重。
同一 reward_id 重复提交不得再次加层；旧 revision、非候选条目、失效职业均拒绝。
取消选择不消耗奖励。

## 强力组件

建议跨职业组件依次为“基础收益”“简化附加效果”“完整联动”；
每组件最多一次，取得后从池中删除，但不删除未取得的后继组件。
前置图必须无环；每个组件单独有效，最后组件满足前置后自动激活完成效果，
自动激活不视为新奖励、不触发龙心或飞升刷新。完整效果不再额外占一个可抽槽。
当前 15 个主条目仅保留设计方向，正式组件应获得独立 ID 并通过依赖测试后接入。

## 刷新与飞升

刷新每奖励最多 1 次、每远征最多 3 次，原子扣次数并使旧候选 revision 失效。
重新执行完整过滤，不强行保证新候选与旧候选不同；已拥有机制绝不返回。
断线后恢复最后已确认的候选、消耗与选择，无法恢复时禁用继续构筑而非复制旧奖励。

飞升按 source_buff/source_reward 记录其贡献层数。再选升级只对该来源此前获得的强化 +2，
仍受各项上限限制；完成后最多生成一次指定奖励。该奖励带 derived 标记，不能触发同根飞升，
也不重复触发龙心；达到成长上限后不再提供升级候选。首次获取护符本身不制造空账本奖励。

## 联动与成长

联动为 data/rules.json 中的 requires/excludes/trigger/emits/priority 等数据。
同事件按 priority 升序，再按 id 稳定排序。每规则每根事件最多一次，
冷却、总次数、层数上限同时生效；同类覆盖使用明确的 reject/strongest/refresh_capped/add_capped。
触发图不能成环；事件祖先含自身时拒绝。深度最多4，单根最多16派生事件。
由词条制造的攻击、获得或返还默认不再次触发同类原生事件。

龙心只对成功提交的原生 Buff 获得计一次；设成长层数与死亡惩罚上限，
死亡不减基础存档属性。倒地与最终死亡分开，复活只重新应用净层数，不再加层。
心之钢默认连续10秒、攻击触发+5本局生命、每玩家×目标50秒CD、总成长300上限；
范围需实测后填写，离开范围重置等待；目标死亡/卸载清理，实例重生不能继承旧键。
Boss 系数初始1，避免未平衡即提高收益。

上述规则还需原生事件适配，独立规则通过测试不代表游戏支持。
