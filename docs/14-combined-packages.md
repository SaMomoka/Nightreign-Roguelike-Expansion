# 遗物与局内奖励整合包

## 解决的问题

遗物生成与局内奖励都交付 `regulation.bin`。在同一个 ME3 配置中叠放两个文件不会自动合并其参数。现在先相对原版比较资源，将两个输入包的改动合成单个文件，再逐资源解密回读验证。

默认取 `local/last-package.json` 指向的遗物包，以及 `local/phase1/tiered_choices-package.json` 指向的奖励包。输入必须通过已有包的完整性和隔离配置检查，并使用同一已审核的原版版本。

## 使用

1. 遗物配置器和局内 Buff 配置器分别生成所需配置；局内配置选择“分层三选一”。
2. 双击根目录 `构建整合实验包.cmd`。只构建，不启动游戏。
3. 需要实机测试时，完全退出游戏，再双击 `启动整合实验包.cmd`，选择配置。

| 配置 | 参数内容 | 存档 |
|---|---|---|
| 生成遗物＋奖励 | 两种修改合成一个文件 | 本包独立 NRE 副本 |
| 只加载局内奖励 | 与输入奖励包完全相同的文件 | 同一副本 |
| 无补丁对照 | 不加载 regulation 覆盖 | 同一副本，保留进度 |

首次启动从 `local/runtime.json` 指定的已有 NRE 隔离种子复制，之后不覆盖进度。不会把两个输入包各自的游戏进度自动合并。取得所选遗物后退出，切到“只加载局内奖励”，可撤除影响随机遗物模板的生成修改。此前遗物持久化已分别实测，本次组合行为仍待实机。

显式指定其他已生成奖励模式：

```powershell
python tools/combined_package.py build --relic "<遗物包目录>" --rewards "<奖励包目录>" --pwsh "<PowerShell7路径>"
```

## 合成规则与证据

- 遗物仅接受 `EquipParamAntique` 和 `ShopLineupParam` 的资源差异。
- 奖励仅接受 `ItemTableParam` 和 `ItemLotParam_enemy` 的资源差异。
- 两输入改动同一资源立即拒绝，不能靠加载顺序解决冲突。
- 输入文件先冻结并核对哈希；输出不覆盖已有包；同版本、同资源顺序、ID、名称和标志均检查。
- 252 个解密资源全部回读核对。本轮实包使用 2 个遗物资源、2 个奖励资源，其余 248 个与原版相同。
- 运行配置的奖励文件与冻结的输入奖励文件逐字节相同。
- 三种配置均由启动器检查，不能切换到正式存档；游戏仍运行时拒绝切换。

入口：`tools/combined_package.py`；合成器：`tools/compose_regulation.ps1`；实文件检查：`tools/check_combined_build.py`。
结果见 `tests/ingame/PHASE1-combined-build.json`。

## 验收边界

用户已暂缓实机。本轮未启动游戏，也未更改任何存档。整合构建通过不等于三选一 UI、叠层上限、按玩家机制去重、复活、远征清理或多人同步通过。Phase 1 仍在开发中。
