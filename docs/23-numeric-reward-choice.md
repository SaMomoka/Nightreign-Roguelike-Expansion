# 数值强化二级选择（训练场实验）

## 用户确认的交互

三选一中的一张卡为“数值强化”。选中后再打开二级列表，任选一种具体加成。不是预先指定数值卡，也不是一次获得全部加成。返回保留该卡的选择机会，不能改领另外两张。

分支 codex/numeric-reward-choice，基准本地 9d2a7d8 / 远端 ed03156。原有 15 类 Buff 需求全部保留，本次仅推进数值组；攻速、移速仍未实现。

## 当前实现与边界

- 一级卡使用自定义物品 8900999，名称“数值强化”，自身不提供属性。原生三选一负责选择一张、放弃其余候选。
- 一级卡领取后由 EMEVD 检测角色的 8900999 效果标记，延迟一秒设置 10009881；仅训练用品箱的空闲 ESD 监听并尝试自动进入二级菜单，训练设置 NPC 不竞争自动打开。此交互路径尚待实测。
- 二级菜单有 12 个加成；选择前检查持有资格。取消不会消耗，重新与训练用品箱交互可以继续。
- 二级选择通过请求旗标 10009900–10009911，由单个事件 10009900 串行处理：检查资格，清除 8900999 效果标记，通过 ItemLotParam_map 1900640000 + 100 × 选项索引（0–11） 领取一种潜在能力，然后重置请求。多个请求不会并发兑换同一份资格。没有 Python 直接注入属性或修改存档。
- 默认三张卡为数值强化、原生翻滚落雷、原生防御反击召唤；训练菜单仍可调整候选。领取资格改用原生潜在能力效果机制，不依赖背包物品计数，实际是否自动弹出菜单、兑换效果及重复叠加均待游戏确认。
- 仅挂接圆桌训练地图。正式远征需要独立的可随处调用 UI 入口与生命周期处理，不能把训练箱的自动菜单视为已经适配局内首领奖励。

## 速度与动作研究

原始 SpEffectParam 没有可直接确认的攻击速度、移动速度倍率。motionInterval 不当作攻速字段。已用 tools/extract_numeric_speed.ps1 从本机 Data0 只读提取 action/script/c0000.hks，当前原件为编译后的 Lua/Havok 字节码，存在 SpeedUpdate、ChangeMoveSpeedIndex 等符号，但符号不能证明可直接调用的方法签名。

[Super Speedy 作者说明](https://www.nexusmods.com/eldenringnightreign/mods/173) 给出了 Nightreign 移动修改先例，并明确不改变攻击速度。没有复制或运行该 Mod 的代码，也未把它作为当前版本可直接套用的证据。后续需可审计地反编译本机版本、识别移动更新路径；攻速还需分离攻击、闪避、前后摇和施法，不能替换成全局动画加速。

### 首次二级选择实测失败及领取类型修正

用户反馈“点击数值强化后依旧是放背包中，且背包内物品无法交互”。只读截图显示停留在“装入背包”格子选择界面，右侧数值强化持有数为 0。之前把 token 设为 goodsType=0，进入了消耗品背包分配流程，不能按已经持有资格解释这次反馈。

修正候选改从原生石剑钥匙 8000 克隆 goodsType=2 的关键物品，不改变原钥匙；保留自己独立的 ID，清除用途限制、消耗、存放和主动使用标志，不占消耗品快捷栏。只作为自定义选择凭证，兑换仍由原生事件扣除自己的 ID。是否成功领取、自动弹窗和兑换效果仍待复测。

凭证类型修正包 `training_buffs_20261024_171619_4d8dc6` 已构建，137 项检查通过，等待重启复测。失败证据见 tests/ingame/NUMERIC-CHOICE-ingame.json。


### 关键物品凭证修正仍失败（最新结论）

用户反馈类型 2 版本仍要求放入消耗品栏，之后不能交互。只读检查当前游戏 EquipParamGoods：8000、8000000、8900000、8900999 均存在，分别与构建文件前 128 字节完全一致；8900999 的 goodsType=2 已实际加载。由此排除“仍启动旧包”或“类型修改没加载”的解释，但不能推定整个物品分类链已经正确。

不再把本方案称为可用的二级选择，也不继续仅凭参数类型换值要求用户重启。下一步需要定位原生掉落卡的物品分类/领取规则，或经用户选择后改用游戏内原生对话菜单完成三选一与二级选择。现有参数构建与纯逻辑测试仍通过，但两版凭证的实机交互均失败。

### 二级选择连发：奖励组隔离修正

用户在 training_buffs_20261024_173522_43011b 回报：“这个数值强化领取后选择后续的任意一项都会给全部选项的加成”。确认已能领取并进入后续选项，但单项发奖失败；用户未单独说明是否自动弹窗，不据此认定自动打开和全部数值准确性均已验收。

查明生成器把十二条独立奖励排为连续 ItemLotParam_map ID 1900640000–1900640011。相邻条目会被奖励组遍历，单次 AwardItemLot 指令并不保证仅发一行。[ItemLotParam 作者文档](https://soulsmodding.wikidot.com/param:itemlotparam) 的 Granting Multiple Items 节说明此行为；本次本地连续布局与实机连发反馈相符。严格而言从中间行应连发后续连续行，用户说“全部”未附逐项数值，因此保留差异，修正版仍需实机验证。

现在每项间隔 100，编号为 1900640000、1900640100，直至 1900641100；完整合成参数表中检查每个奖励前后相邻行均不存在，避免与原版或其他 Mod 行意外连接。原生三卡 UI、效果标记、二级菜单和数值定义不变。

新增回归检查覆盖两页十二项的连续奖励组展开，以及每个事件分支的所选 lot。将旧连续分配代入新检查，十二个子用例全部拒绝；修正后 140 项 unittest 与 validate 通过。此前事件模拟只记录 AwardItemLot 调用次数，未覆盖该指令内部奖励组展开，因此未发现此问题。

不能用已领取整组效果的角色对照修正版的单项属性。下一包使用新的隔离存档；需核对选择生命只改生命、选择 FP 只改 FP，以及第二页一项不连发其他项。旧版失败记录保留。
