# 数值强化二级选择（训练场实验）

## 用户确认的交互

三选一中的一张卡为“数值强化”。选中后再打开二级列表，任选一种具体加成。不是预先指定数值卡，也不是一次获得全部加成。返回保留该卡的选择机会，不能改领另外两张。

分支 codex/numeric-reward-choice，基准本地 9d2a7d8 / 远端 ed03156。原有 15 类 Buff 需求全部保留，本次仅推进数值组；攻速、移速仍未实现。

## 当前实现与边界

- 一级卡使用自定义物品 8900999，名称“数值强化”，自身不提供属性。原生三选一负责选择一张、放弃其余候选。
- 一级卡领取后由 EMEVD 检测物品，延迟一秒设置 10009881；仅训练用品箱的空闲 ESD 监听并尝试自动进入二级菜单，训练设置 NPC 不竞争自动打开。此交互路径尚待实测。
- 二级菜单有 12 个加成；选择前检查持有资格。取消不会消耗，重新与训练用品箱交互可以继续。
- 二级选择通过请求旗标 10009900–10009911，由单个事件 10009900 串行处理：检查资格，删除一份 8900999，通过 ItemLotParam_map 1900640000–1900640011 领取一种潜在能力，然后重置请求。多个请求不会并发兑换同一份资格。没有 Python 直接注入属性或修改存档。
- 默认三张卡为数值强化、原生翻滚落雷、原生防御反击召唤；训练菜单仍可调整候选。领取资格物品占用正常物品机制，实际是否自动弹出菜单、兑换效果及重复叠加均待游戏确认。
- 仅挂接圆桌训练地图。正式远征需要独立的可随处调用 UI 入口与生命周期处理，不能把训练箱的自动菜单视为已经适配局内首领奖励。

## 速度与动作研究

原始 SpEffectParam 没有可直接确认的攻击速度、移动速度倍率。motionInterval 不当作攻速字段。已用 tools/extract_numeric_speed.ps1 从本机 Data0 只读提取 action/script/c0000.hks，当前原件为编译后的 Lua/Havok 字节码，存在 SpeedUpdate、ChangeMoveSpeedIndex 等符号，但符号不能证明可直接调用的方法签名。

[Super Speedy 作者说明](https://www.nexusmods.com/eldenringnightreign/mods/173) 给出了 Nightreign 移动修改先例，并明确不改变攻击速度。没有复制或运行该 Mod 的代码，也未把它作为当前版本可直接套用的证据。后续需可审计地反编译本机版本、识别移动更新路径；攻速还需分离攻击、闪避、前后摇和施法，不能替换成全局动画加速。

### 首次二级选择实测失败及领取类型修正

用户反馈“点击数值强化后依旧是放背包中，且背包内物品无法交互”。只读截图显示停留在“装入背包”格子选择界面，右侧数值强化持有数为 0。之前把 token 设为 goodsType=0，进入了消耗品背包分配流程，不能按已经持有资格解释这次反馈。

修正候选改从原生石剑钥匙 8000 克隆 goodsType=2 的关键物品，不改变原钥匙；保留自己独立的 ID，清除用途限制、消耗、存放和主动使用标志，不占消耗品快捷栏。只作为自定义选择凭证，兑换仍由原生事件扣除自己的 ID。是否成功领取、自动弹窗和兑换效果仍待复测。

凭证类型修正包 `training_buffs_20261024_171619_4d8dc6` 已构建，137 项检查通过，等待重启复测。失败证据见 tests/ingame/NUMERIC-CHOICE-ingame.json。
