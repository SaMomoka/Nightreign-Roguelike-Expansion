# Phase 1：普通/稀有分层候选

本轮继续真实奖励参数接入。用户已明确暂缓实机验证，本轮不启动或操作游戏。

## 现在能做什么

打开根目录`启动局内Buff配置器.cmd`，选择新增模式：
**分层三选一：独立池 + 普通 / 稀有**。
设置普通、稀有两档权重，保存预设或生成独立实验包。
默认75:25；可将一档设为0，不能同时为0。整数范围0–65535。
六项数值Buff的条目权重同时作用于其普通和稀有原生版本。

这实现的是原生奖励表的两层权重：先选稀有档，再在该档内选条目。
没有通过外部Python抽奖后冒充游戏奖励；Python只编译真实ItemTable参数及校验结果。
实际抽取由游戏读取新的ItemTableParam完成，行为仍待实机确认。
金色、红色稀有池尚未接入，不能把普通/稀有直接称为任务书全部四档稀有度已完成。

## 数据与修改范围

|分类|普通原生池|稀有原生池|总候选数|
|---|---:|---:|---:|
|生存|4200101|4200301|10|
|攻击|4200102|4200302|8|
|防御|4200103|4200303|8|

物品经EquipParamGoods → PermanentBuffParam → SpEffectParam核对。
六项可调目标的稀有版本来自显式ID映射，不将“ID+1”当作适用于所有词条的规律。
三个分类的普通+稀有集合一起检查，物品ID和实际SpEffect不能跨分类重复。

编译器创建9个项目专用池：3个稀有档选择池、6个条目池。
新增32行：26条原生条目副本，6条引用子池的行。
嵌套行模板取自原件ItemTableParam1200600中指向4200100的category=7记录；
它证明当前版本有池引用池的参数表示，不证明我们新路径已经游戏验收。
叶子条目的效果、数量、职业、事件旗标、NT/unknown字段全部沿用原件。

只改堡垒ItemLotParam_enemy6000050–6000052中8处已有正权重引用；
不更改34730条原有ItemTable行，不更改SpEffect、PermanentBuff或Goods。
因此与旧weighted模式不同，不会因修改共享4200100池而影响其287个敌人掉落引用。
仅保证本次声明修改范围；不据此宣称无缝兼容。

## 项目ID分配

`1900100000–1900100008`是本工程明确新分配的ItemTable池ID，
**不是声称游戏原来已有这些ID**。构建前检查原件碰撞及排序，发生冲突直接拒绝。
三个入口为1900100000、1900100003、1900100006，各自引用后续两个叶子池。
当前构建固定本机原版散列，不支持直接合并未知整合包regulation。
遗物已经生成后可以在无遗物生成覆盖的隔离副本使用局内包；没有实现自动存档迁移或多包合并。

## 概率与防循环

编译结果附`probability_report`，使用精确分数展开整个项目池图。
逐个候选概率之和必须为1，递归路径先检查缺失引用、循环、空池及负权重。
零权重边也检查循环，避免日后调权重才暴露潜在环。

默认六项条目权重200、其余条目100、普通/稀有75:25时：

|对应选择槽内的候选|静态参数权重占比|
|---|---:|
|生命普通版|18.75%|
|生命稀有版|6.25%|
|物理攻击普通版|30%|
|物理攻击稀有版|10%|
|物理减伤普通版|25%|
|物理减伤稀有版|1/12，约8.333%|

以上是单个槽内的参数计算，既不是整场远征掉落率，也不是游戏统计实测概率。
是否按该图解析、三槽是否正确展示、重复领取和清理都仍待验证。

## 构建与拒绝测试

新构建器`tools/build_reward_pools.ps1`独立于遗物/旧奖励字段编辑器，
专门处理受限的原生模板克隆与堡垒引用修改。
写入后解密回读，比较所有预期行、原有行以及其他资源。
正式输出只在全部比较通过后从.unverified.bin改名。

```powershell
python tools/phase1_package.py build --mode tiered_choices
python tools/check_reward_tiers.py --pwsh (Get-Command pwsh).Source
python tools/validate.py
python -m unittest discover -s tests
```

8类坏清单均必须拒绝：循环、缺失子池、空入口、ID碰撞、错误模板行序、
权重越界、不允许改的字段、错误奖励入口。
测试日志见`tests/ingame/PHASE1-tiered-build.json`；状态始终game_verified=false。
