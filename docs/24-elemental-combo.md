# BUFF-001 元素连击与隐士式调和：模板研究与规则原型

## 状态与范围

数值强化单项发放已获用户实测通过。本任务基于该版本，新分支 codex/elemental-combo。当前交付为本机原生模板引用分析、可重复导出工具和规则原型；尚未生成可领取的 BUFF-001，也未启动新的实机包。data/buffs.json 保持 disabled / theoretical，避免把纯逻辑实现误当成游戏实现。

需求：累计 N 次有效命中后，下一击附加元素和敌方标记；不同标记组合触发伤害或以敌人为中心的友方增益。首版武器绑定，不能误变为持有武器即角色全局被动。每敌人独立 CD、标记过期、联机去重全部保留。

## 本机原生模板证据

来自原件 regulation 10350000，哈希及结构化引用见 data/elemental_template_references.json。Smithbox NR 行名用于定位，结论再对照真实参数行；第三方行名不等于实机效果验证。

- MixcraftMagicParam 含 1 个空行和 64 个有序配方，完整覆盖四种元素的三槽排列，映射到 14 个 Magic 法术。同一多重集合的不同顺序映射一致。元素码由纯元素配方和对应法术交叉核对：1 魔力、2 火、3 雷、4 圣。
- Magic 8000–8003 为四个纯元素结果；8010–8015 为两类元素组合；8020–8023 为三类元素组合。Magic 的有效引用继续连到 Bullet、AtkParam_Pc、SpEffectParam。不能把“有配置表”解释为任意敌人都能自动使用隐士的三槽收集逻辑。
- 706000–706003 是吸收后效果，stateInfo=2263，寿命 0.3 秒；replaceSpEffectId 分别为 7500602、7500601、7500603、7500604。后四行是有 stateInfo=2396 前提的遗物减伤效果。这不是已经找到的敌方标记存储；直接将这四行挂敌人身上不能证明会生成可调和标记。
- 连续攻击模板 320800 等使用 stateInfo=303、accumuOverVal=17/30/45/60；6900–6909 的 accumuVal 为 2、4……20。因此原生累积不是固定命中次数，不能把阈值 3 当作三次攻击。
- Magic 8003 的 Bullet 10800300 引用在当前原件缺失；同法术仍有 SpEffect 1800300。工具记录未解析引用，不将缺失行伪造成可用模板。

## 可优先复用的结果

| 组合 | 原生结果链 | 需要改造的边界 |
| --- | --- | --- |
| 火 + 雷 | Magic 8011 → Bullet 10801100 → AtkParam_Pc 81100 | 将生成位置设为目标中心；保留玩家归属与敌我过滤，不把敌人当施法者 |
| 魔 + 圣 | Magic 8014 → Bullet 10801400 → AtkParam_Pc 81400 + SpEffect 1801400 | 已有范围护盾模板；需验证敌人中心生成时仍只影响玩家友方 |
| 火 + 圣 | Magic 8012 → Bullet 10801200/1/2 | 包含减最大生命、提高最大生命、治疗及异常清除多条效果，不能把整条复制成普通回血 Buff |
| 魔 + 火 + 雷 | Magic 8020 → 多级 Bullet → AtkParam_Pc 82000/82010/82011/82012 | 吸引和爆发分开，多级伤害不得反馈为新的有效连击 |
| 魔 + 火 + 圣 | Magic 8021 → Bullet 10802100/1 | 伤害与友方 HP/FP 恢复通道分开，需保留目标关系 |

研究阶段优先用“火雷爆发”和“魔圣护盾”做伤害/增益两类模板探针。该选择是研发顺序，不删除另外十二类结果。

## 规则原型与暂定值

tools/elemental_combo.py 是纯规则模型，不读写游戏。默认 N=3，完成三次后第四次有效命中附加元素；为可重复测试采用魔→火→雷→圣轮换，随机策略以后接入。标记寿命暂定 12 秒，目标 CD 暂定 8 秒。这些是实验默认值，不是已定平衡数值。

当前原型先以三个不同元素触发三元素组合；两元素何时提前结算还需与三元素积累规则一起实现，不能简单在第二种出现时立刻消耗，否则永远到不了三元素组合。建议正式规则使用三个充能槽，重复元素占槽，按原生配方映射，再决定是否允许纯元素结果；当前模型尚未实现此扩展，不声称支持完整 14 种组合。

命中必须携带 run、owner、weapon-instance、target、attack-instance 和时间。直接伤害且该武器处于装备状态才接受。相同攻击对同一敌人只记一次；组合/持续伤害不计数；空挥和零伤害不计数。多目标一次攻击对不同目标的计数暂按每目标一次，正式平衡仍可调整。

计数按玩家×武器保存，标记按玩家×敌人保存，组合 CD 按敌人共享。组合结算先占用 CD，再清除该敌人的标记，阻止多人同帧重复结算；不混用其他玩家未授权的元素归属。主机权威及实际同步接口尚未实现。切走武器清除蓄积是首版保守策略；倒地/远征结束必须由未来适配器调用清理。

## 仍须定位的真实接口

1. 命中事件：需要武器实例、攻击实例、受击者、来源玩家。AttachEffectParam.onHitSpEffect 有原生实例，但是否应用到敌人、特效是否保留归属，仍需实测。不能以“字段名叫 onHit”代替验证。
2. 原生敌方元素残留：目前定位的是吸收后的玩家效果，不是敌方残留组件。应比较隐士对同一敌人造成属性伤害前后、吸取前后的状态；若无法复用，需要原创敌方标记而不干扰原生残留。
3. 结果释放：在敌人坐标创建 Bullet，来源保留原攻击者；分别验证伤害对象和护盾友方过滤。只给敌人 SetSpEffect 可能错误地令敌人成为友方增益的所有者。
4. 武器绑定：主手、副手、仅背包、切换、双持、卸下、倒地、远征结束分别验证，尚无这些接口证据，不能开启此 Buff。
